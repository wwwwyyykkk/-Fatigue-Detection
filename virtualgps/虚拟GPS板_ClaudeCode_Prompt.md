# 项目任务：虚拟GPS模拟板（ESP32-S3，独立工程）

## 背景

这是"驾盾"疲劳驾驶检测系统的配套子项目。主系统跑在另一块 ESP32-S3 上（负责摄像头、疲劳检测、人脸识别），由于答辩现场无法获取真实GPS信号，老师要求做一块独立的 ESP32-S3 板来模拟GPS/驾驶场景数据，通过 UART 串口把模拟数据发送给主控板。

**这块板要新建一个完全独立的 ESP-IDF 工程，和主控板项目没有任何代码共享。**

## 硬件清单

- ESP32-S3 DevKitC-1（独立的一块，区别于主控板）
- ADC按键分压电路：1个ADC引脚通过电阻分压识别6个按键（电路已设计好，见下方"ADC按键设计"）
- SSD1306 OLED 显示屏（I2C接口）
- 3根UART线连接主控板（TX/RX/GND）

## 开发环境

- ESP-IDF v5.5.4，路径 `D:\ESP\.espressif\v5.5.4\esp-idf`
- 已知坑：组件管理器联网检查经常卡死，新建工程后**第一次编译前**务必先执行：
  ```powershell
  $env:IDF_COMPONENT_MANAGER_ENABLED = "0"
  ```
- 如果用到 `esp-who` 工具链（这个项目大概率不需要），不要设置 `IDF_EXTRA_ACTIONS_PATH`，否则会触发 `edit-manifest` 卡死编译

## 功能需求

### 1. ADC按键设计（已确定，照此实现）

单个ADC引脚通过分压电路识别6个独立按键，电路原理：

```
3.3V → R14(10kΩ)上拉 → ADC采样点 → 6个按键并联，每个按键分别串联不同下拉电阻到GND

按键1 (SW1): 下拉电阻 1kΩ    → 理论电压 ≈0.30V
按键2 (SW2): 下拉电阻 2kΩ    → 理论电压 ≈0.55V
按键3 (SW3): 下拉电阻 3.9kΩ  → 理论电压 ≈0.94V
按键4 (SW4): 下拉电阻 8.2kΩ  → 理论电压 ≈1.48V
按键5 (SW5): 下拉电阻 16kΩ   → 理论电压 ≈2.03V
按键6 (SW6): 下拉电阻 33kΩ   → 理论电压 ≈2.52V
无按键按下:                  → 电压 ≈3.3V (上拉直通)
```

**重要**：实际电压会因ESP32 ADC非线性和电阻误差有偏差，代码里请先实现一个独立的"ADC校准模式"，开机时打印原始ADC读数和换算电压，方便我们用实测值校准判断区间，而不是直接用上面的理论计算值硬编码阈值。

按键去重防抖：连续3次采样（每次间隔约20ms）读到同一档位才确认为有效按键。

### 2. 六个按键的功能映射

按键不是简单的"速度档位"，而是覆盖四个独立维度，需要状态机管理：

| 按键 | 功能 | 行为 |
|------|------|------|
| SW1 | 速度 = 0 km/h | 设置当前速度值，立即生效 |
| SW2 | 速度 = 80 km/h | 设置当前速度值，立即生效 |
| SW3 | 速度 = 150 km/h（超速） | 设置当前速度值，立即生效 |
| SW4 | 地点循环切换 | 普通路段 → 服务区 → 应急车道 → 循环 |
| SW5 | 司机切换 | 司机1 ↔ 司机2 切换 |
| SW6 | 驾驶时长快进 | 每按一次，累计驾驶时长 +60分钟（用于演示连续驾驶4小时强制休息触发逻辑，货车司机连续驾驶不得超过4小时，3.5小时应有预警） |

全局状态结构体：

```c
typedef enum {
    LOCATION_NORMAL = 0,      // 普通路段，不可停车休息
    LOCATION_SERVICE_AREA,    // 服务区，可以停车休息
    LOCATION_EMERGENCY_LANE   // 应急车道，禁止停车（违规）
} location_type_t;

typedef struct {
    float speed_kmh;
    location_type_t location;
    int driver_id;              // 1 或 2
    int drive_duration_min;     // 累计驾驶分钟数
} virtual_gps_state_t;
```

### 3. OLED显示

实时显示当前模拟状态，四行布局：

```
Speed: 80 km/h
Loc: Service Area
Driver: #1
Drive: 3h20min
```

每次按键状态变化后立即刷新显示。

### 4. UART通信协议（发送端）

通过UART2（或可配置的UART口，引脚留作可调整参数）每秒发送一次心跳，状态变化时立即额外发送一次。

**协议格式（纯文本，方便调试时直接用串口监视器看）：**

```
SPEED,LOCATION,DRIVER,DURATION\n

示例：80,1,1,200\n
含义：速度80km/h，location=1(服务区)，司机1，已驾驶200分钟
```

UART参数：115200 baud，8N1，具体使用的GPIO引脚请在代码注释中明确标注，方便后续接线。

### 5. 代码结构要求

- 用标准 ESP-IDF（C或C++都可以，不要引入额外重型框架）
- FreeRTOS 任务划分：
  - 一个任务负责ADC按键扫描+防抖
  - 一个任务负责UART定时发送（1秒心跳）
  - 按键状态变化时通过事件或队列触发OLED刷新和UART立即发送
- 代码要有清晰的注释，特别是ADC阈值判断部分和UART协议部分，因为后续要调试和可能修改阈值
- main.c 里的 app_main 保持简洁，复杂逻辑拆到独立的 .c/.h 文件里（比如 `adc_buttons.c`, `oled_display.c`, `uart_protocol.c`）
