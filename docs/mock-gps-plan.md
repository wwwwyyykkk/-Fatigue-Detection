# Mock GPS 模拟器 — 设计方案

## 一、背景

疲劳检测系统演示时存在两个问题：
1. **室内无 GPS 信号**，无法定位
2. **无法模拟不同车速**，不能演示速度变化场景

教师建议增加 **ADC 按键 + OLED 显示屏**，手动模拟 GPS 数据，喂给现有的云上报代码。

## 二、硬件方案

### 2.1 选型

| 部件 | 型号 | 数量 | 接口 |
|------|------|------|------|
| OLED 显示屏 | SSD1306 128x64 0.96寸 | 1 | I2C |
| 按键 | 6×6mm 轻触开关 | 6 | ADC 分压（共用 1 个引脚） |
| 电阻 | E12 系列 1k/2.2k/4.7k/10k/22k/47k | 各 1 | 分压网络 |
| 上拉电阻 | 10k | 1 | 接 3.3V |

### 2.2 引脚分配

| 信号 | GPIO | 备注 |
|------|------|------|
| ADC 按键输入 | **GPIO7** (ADC1_CH6) | 12bit，单次采样 |
| I2C SDA | **GPIO11** | SSD1306 数据 |
| I2C SCL | **GPIO12** | SSD1306 时钟 |
| OLED VCC | 3.3V | — |
| OLED GND | GND | — |

### 2.3 ADC 按键分压电路

```
3.3V ── 10k ─┬── ADC_GPIO7
             │
             ├──[1kΩ ]── SW1 ── GND   🚛 速度 0 km/h
             ├──[2.2k]── SW2 ── GND   🚛 速度 60 km/h
             ├──[4.7k]── SW3 ── GND   🚛 速度 90 km/h
             ├──[10k ]── SW4 ── GND   🚛 速度 130 km/h
             ├──[22k ]── SW5 ── GND   ⏱ 时长 3.5 h
             └──[47k ]── SW6 ── GND   ⏱ 时长 4 h
```

6 个阻值均为 E12 系列常用值，任意电子市场可买到。各按键 ADC 原始值间隔 > 350 counts（12bit），抗噪充足。

### 2.4 ADC 按键阈值表（理论值）

| 按键 | 电阻 | 分压(V) | ADC Raw(约) | 间隔 |
|------|------|---------|-------------|------|
| 无按键 | 开路 | 3.30 | 4050~4095 | — |
| BTN1 (0km/h) | 1kΩ | 0.30 | ~370 | 350+ |
| BTN2 (60km/h) | 2.2kΩ | 0.60 | ~740 | 350+ |
| BTN3 (90km/h) | 4.7kΩ | 1.06 | ~1310 | 550+ |
| BTN4 (130km/h) | 10kΩ | 1.65 | ~2050 | 700+ |
| BTN5 (3.5h) | 22kΩ | 2.27 | ~2820 | 750+ |
| BTN6 (4h) | 47kΩ | 2.72 | ~3370 | 550+ |

## 三、按键功能定义

### 3.1 按键分配

| 按键 | 功能 | 详细说明 |
|------|------|----------|
| BTN1 | 🚛 **速度 0 km/h** | 停车、怠速、服务区休息 |
| BTN2 | 🚛 **速度 60 km/h** | 低速行驶、重载爬坡、高速拥堵 |
| BTN3 | 🚛 **速度 90 km/h** | 正常高速巡航 |
| BTN4 | 🚛 **速度 130 km/h** | 🚨 **超速**（超货车限速 100 km/h） |
| BTN5 | ⏱ **时长 3.5 小时** | 按此键启动模拟 / 修改剩余时长 |
| BTN6 | ⏱ **时长 4 小时** | 按此键启动模拟 / 修改剩余时长 |

### 3.2 操作逻辑

```
┌─────────────────────────────────────────────────────────┐
│  速度和时长分开控制，时长键也是"启动"信号                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ① 上电 → OLED 显示 "速度: --  时长: -- [请选择]"       │
│                                                         │
│  ② 按 BTN2 (60km/h) → OLED "速度: 60 km/h [待启动]"     │
│     (速度已选但模拟尚未开始)                              │
│                                                         │
│  ③ 按 BTN5 (3.5h) → ✅ 模拟开始！                        │
│     → 坐标以 60km/h 生成，3.5h 倒计时                     │
│                                                         │
│  ④ 运行中按 BTN4 (130km/h)                              │
│     → 实时切换速度，OLED 马上显示 🚨 超速                  │
│                                                         │
│  ⑤ 运行中按 BTN6 (4h)                                   │
│     → 剩余时长改为 4h                                    │
│                                                         │
│  ⑥ 时长耗尽 → 模拟自动停止，显示"已结束"                  │
│                                                         │
│  ⑦ 重新选速度 + 按时长键 → 重新开始                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.3 提醒触发

| 条件 | 动作 |
|------|------|
| 速度 ≥ 100 km/h | OLED 实时显示 `🚨 超速！` 标记 |
| 连续驾驶 ≥ 3 小时 30 分 | 播放 `drive_long.wav` 语音 "已连续驾驶超过3.5小时，请停车休息" |
| 疲劳等级变化（来自摄像头） | 播放 `mild.wav` / `severe.wav` 疲劳告警 |

### 4.2 新增 FreeRTOS 任务

| 属性 | 值 |
|------|-----|
| 任务名 | `gps_sim` |
| 优先级 | **6** |
| 栈大小 | **4096 字节** |
| 运行频率 | **1 Hz**（每秒 tick 一次） |

优先级说明：
- `uvc_frame`（摄像头处理）= 13
- `voice_play`（语音播报）= 8
- **`gps_sim`（GPS 模拟）= 6**，不干扰实时流水线

### 4.3 数据流

```
┌──────────────────┐    ┌──────────────────┐    ┌────────────────┐
│ frame_handling   │    │ mock_gps_task    │    │   Cloud 代码   │
│ (prio 13)        │    │ (prio 6)         │    │                │
├──────────────────┤    ├──────────────────┤    ├────────────────┤
│ [每处理一帧]     │    │                  │    │                │
│ ──── fatigue ──► │    │ [1Hz] 读取共享   │    │                │
│ level / perclos  │    │   疲劳数据        │    │                │
│                  │    │                  │    │                │
│                  │    │ [1Hz] 扫描 ADC   │    │                │
│                  │    │   按键           │    │                │
│                  │    │                  │    │                │
│                  │    │ [1Hz] 更新坐标   │    │                │
│                  │    │   航向漂移+抖动  │    │                │
│                  │    │                  │    │                │
│                  │    │ [1Hz] 刷新 OLED  │    │                │
│                  │    │                  │    │                │
│                  │    │ [1Hz] callback───►    │ 收到坐标数据  │
│                  │    │  gps_data_point_t│    │ 上传云端      │
└──────────────────┘    └──────────────────┘    └────────────────┘
```

### 4.4 Cloud 上报数据契约

```c
typedef struct {
    double    latitude;         // 纬度（WGS84）
    double    longitude;        // 经度（WGS84）
    float     speed_kmh;        // 当前速度（km/h）
    float     heading_deg;      // 航向（0~359°）
    uint32_t  elapsed_sec;      // 已运行秒数
    uint32_t  total_sec;        // 总时长秒数
    bool      overspeed;        // 是否超速（>100 km/h）
    bool      overtime;         // 是否超时（≥3.5h）
    bool      has_fix;          // GPS 是否锁定
    uint64_t  timestamp_us;     // 时间戳
} gps_data_point_t;
```

cloud 代码通过两种方式获取数据：

**方式一：回调注册**
```c
mock_gps_register_callback(my_upload_cb, NULL);
// 自动在 1Hz 循环中收到坐标更新
```

**方式二：轮询**
```c
const gps_data_point_t *gps = mock_gps_get_latest();
// 在自己的循环里取最新坐标
```

## 六、坐标生成算法

每秒 tick 一次，模拟货车从北京向天津方向行驶。

```
① 读取当前速度 v (km/h) → 转换为 m/s

② 移动距离 d = v_mps × 1s（米）

③ 航向漂移 heading += 随机(-20°, +20°)/s

④ 经纬度变化（WGS84）：
   dlat = d × cos(heading) / 111320
   dlng = d × sin(heading) / (111320 × cos(lat))

⑤ 加入 GPS 抖动：±5m 随机偏移

⑥ 如果累计路程 > 500km → 折返起点（循环）
```

起始坐标统一设定为 **北京海淀区**（39.95°N, 116.31°E），朝东南方向（天津方向）行驶。
